## Titel-Änderung: welche Portal-Screens anders wirken

CRM-Titel (`resolveAkteVorgangTitel`) statt bisherigem Portal-`buildTitel` (`Situation — Bereich — PLZ`).  
Sichtbarer Effekt überall, wo `resolveVorgang().titel` oder dieselbe Akte-Logik genutzt wird — **sobald** Angebot/Auftrag-Titel-Felder durchgereicht werden:

| Screen / Oberfläche | Vorher (typisch) | Nachher (CRM) |
|---------------------|------------------|---------------|
| Kunde-Portal Vorgangsliste / Karten (`build-kunde-vorgaenge` → `resolveListCardTitle`) | oft schon Akte-Titel; Fallback Situation·Bereich | unverändert Akte; Resolver-intern jetzt deckungsgleich |
| Kunde-/HV-Vorgang-Detail (Titel aus List-Item) | wie Liste | Leistungsumfang / Auftragstitel / Situation · Bereich (Labels), **ohne PLZ** im Resolver-Titel |
| Partner-Karten / Partner-Dashboard (`partner-vorgang-display`, Listen-Titel) | Auftragstitel / Partner-Helfer | bei Resolver-Pfad: CRM-Akte; Listen weiter über `partner-listen-titel` |
| HV-Dashboard Flow-Counts | nutzt Resolver nur für Phase/Flow, nicht Titel | Titel-UI unverändert; Phase/Actor jetzt CRM-kanonisch |
| Org-HV Vorgangsliste / Detail | eigene Titel-Helfer (`melde-vorgang-titel` etc.) | kein direkter Resolver-Titel-Swap; Status über CRM-Resolver |
| Eigentümer- / Hausmeister-Portale | List-Titel über Portal-Builder | wie Kunde: Akte-Logik, kein `Situation — PLZ`-Resolver-Titel mehr |

**Kurz:** Wer früher den **Resolver-Titel** als `situation — bereich — plz` sah, sieht jetzt **Leistungsumfang / Auftrag / Situation · Bereich** (wie CRM). Screens, die Titel lokal bauen (Melde-Titel, Partner-Listen), ändern sich nur, wenn sie auf `resolveVorgang().titel` umgestellt sind.
